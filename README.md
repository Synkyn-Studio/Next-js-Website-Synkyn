# Synkyn Studios — Next.js

The Synkyn Studios site (previously static HTML/CSS/JS) on the Next.js App
Router. Same design, content, animations and SEO; no backend, no API routes, no
database — every route is prerendered as static HTML at build time.

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # static prerender of every route
npm start       # serve the production build
npm run typecheck
```

## Routes

| Route | Was | Notes |
| --- | --- | --- |
| `/` | `index.html` | Loading screen, hero showreel, pipeline journey, sponsors |
| `/about-us` | `about-us.html` | Origin story, chroma team grid (`#team`) |
| `/library` | `library.html` | Bento works grid + media modal (deep links like `#work-nbk111`) |
| `/contact` | `contact.html` | One-click email CTAs, FAQ |
| `/printalbum` | `printalbum.html` | Filterable print gallery + lightbox (`#project-1`) |
| `/terms` | `terms.html` | Legal document with table of contents |
| `not-found` | `404.html` | Zero-gravity 404, served for any unknown URL |

Old `*.html` URLs permanently redirect to the clean ones (`next.config.ts`),
so existing links and search results keep working. `robots.txt` and
`sitemap.xml` are generated by `src/app/robots.ts` and `src/app/sitemap.ts`.

## Structure

```
public/            images, video, fonts, vendor libraries, assets/*.css (unprocessed)
src/app/           routes, metadata, robots + sitemap
src/components/    layout chrome, per-page sections, small shared UI
src/behaviors/     the original scripts, ported to disposable behaviours
src/lib/runtime/   vendor loader, Scope, Lenis manager, React hooks
src/data/          content data (works, prints, team, SEO, structured data)
src/styles/        per-page and shared CSS, inlined per route
```

### How the original JavaScript was migrated

The static pages ran their scripts once per document load. With client-side
navigation a page mounts and unmounts repeatedly, so every script became a
*behaviour*: a function that receives a `Scope` (`src/lib/runtime/scope.ts`)
and registers listeners, timers, animation frames, observers, Lenis
subscriptions and GSAP tweens through it. Leaving a route disposes the scope,
which removes all of them and reverts the route's GSAP context, so nothing
leaks between pages.

Behaviours are attached with two hooks (`src/lib/runtime/use-behavior.ts`):

- `useImmediateBehavior` — scripts that ran inline while the page parsed.
- `useBehavior` — scripts that needed GSAP/Lenis, i.e. the deferred vendor
  bundles and `DOMContentLoaded` handlers. It waits for
  `whenRuntimeReady()`, which loads `/public/vendor/*` in the original order
  and creates the shared Lenis instance.

GSAP, ScrollTrigger, SplitText, DrawSVG, MotionPath, Lenis and Springer are
still the exact files from `/public/vendor`, loaded as classic scripts, so
their versions and behaviour are unchanged.

`main.js` (a large template bundle) was not carried over wholesale; only the
modules these pages actually used were ported: the theme class, the header
scroll state, the desktop mega menus, the mobile panel, the gradual blur bar,
the `[data-ns-animate]` reveal engine, the chroma grid/spotlight, the footer
divider tween and the hero video modal.

### CSS

`main.css` (with its `@import "./cursors.css"`), `navbar.css` and `footer.css`
are served byte-for-byte from `public/assets` and linked in the root layout.
They deliberately bypass Next's CSS pipeline: minification merges navbar.css's
duplicate `.header-two` rules and drops its `translate: none !important`
reset, which double-shifts the fixed header. Bump `ASSET_VERSION` in
`src/lib/site.ts` after editing them to bust caches.

Page-specific CSS lives in `src/styles/pages/**` and is inlined per route by
`PageStyle`. Next keeps route CSS imports alive after client-side navigation,
and these pages' theme blocks conflict with one another (for example
`overflow-x: clip` vs `hidden` on `html, body`), so each route's CSS is
rendered in the React tree and removed with the route. Blocks that were
identical across pages live in `src/styles/shared/`.

### Images

Local team photos use `next/image`. The rest of the markup keeps plain `<img>`
tags: most images are remote (ImageKit, already a transforming CDN) or are
sized by the original CSS, where swapping in the image component would change
the markup the stylesheets target.

## Known issues inherited from the original site

- `images/hero-poster.webp` is referenced by the home hero but missing from the
  project. The hero video controller hides the poster on error, so it only
  costs a 404 request; drop the file in `public/images/` to get the intended
  poster-first hero.
- `assets/main5.js`, `assets/loader.css` and `vendor/stack-card.min.js`,
  `vendor/leaflet.min.js`, `vendor/swiper.min.js` etc. were referenced by the
  template bundle but never used by these pages, so they were not carried over.
- The Vimeo embeds and Google Tag Manager are third-party; they log their own
  console messages exactly as before.
